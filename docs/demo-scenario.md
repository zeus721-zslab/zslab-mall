# 시연 시나리오

## 1. 목적

구매자·셀러·관리자 3역할을 오가며 가입부터 정산까지 한 흐름으로 30분 안에 확인하는 시연 순서다. 화면별 세부 조작은 [관련 자료](#6-관련-자료)에 맡기고, 이 문서는 역할을 바꾸는 순서, 품목 준비, 단계마다 확인할 곳만 적는다.

## 2. 준비

**로그인.** 구매자는 `/signup`에서 새로 가입한다. 공유 데모 계정의 주문·클레임과 섞이지 않게 하기 위해서다. 가입하면 바로 로그인된다. 셀러는 `/seller/login`의 "셀러 데모 로그인" 버튼(데모 패션랩)을, 관리자는 `/admin/login`의 "관리자 데모 로그인" 버튼을 쓴다. 역할마다 브라우저 창(또는 시크릿 창)을 따로 두면 전환이 빠르다.

**주문 구성.** 한 주문에 데모 패션랩 상품 2개와 다른 데모 셀러 상품 1개를 담는다. 패션랩 상품 하나는 구매확정용, 다른 하나는 반품용이고, 다른 셀러 상품은 취소용이다. 이 구분은 시스템이 나누는 것이 아니라 시연에서 품목마다 맡기는 역할이다.

## 3. 순서

| 단계 | 역할 | 화면 경로 | 확인 포인트 |
|---|---|---|---|
| 1. 가입 | 구매자 | `/signup` | 가입 직후 로그인 상태 |
| 2. 탐색·장바구니 | 구매자 | `/products` → `/cart` | 장바구니에 셀러 2곳의 상품 3개가 담김 |
| 3. 주문·mock 결제 | 구매자 | `/checkout` → `/payment/mock`에서 SUCCESS | 결제 완료 화면 · 주문 상세에서 품목 3개 결제완료 |
| 4. 셀러별 표시 확인 | 구매자·셀러 | `/orders/:id` · `/seller/orders` | 구매자 주문 상세가 셀러별로 묶여 보임 · 패션랩 셀러 화면에는 자기 품목 2개만 보임 |
| 5. 취소 | 구매자 → 관리자 | `/claims/new` → `/admin/orders/claims` "승인" | 송장 등록 전 품목(취소용)만 취소 가능 · 승인 뒤 환불 완료, 품목 취소 |
| 6. 송장·배송완료 | 셀러 | `/seller/orders`(송장 등록) → `/seller/deliveries`(배송완료) | 패션랩 품목 2개가 배송완료로 바뀜 |
| 7. 구매확정 | 구매자 | `/orders/:id` | 구매확정용 품목만 확정 · 확정 뒤에는 반품·교환 불가 |
| 8. 반품 요청 | 구매자 | `/claims/new` | 반품용 품목 · 사유 "상품 불량" · 사진 첨부 |
| 9. 반품 처리 | 관리자 | `/admin/orders/claims` "승인" → "회수 송장 대행 등록" → "회수 확인" → "검수" | 검수 통과 뒤 자동 환불 |
| 10. 환불 완료 | 구매자·관리자 | `/claims/:id` · `/admin/orders/:id` | 양쪽에서 환불 완료 · 첨부 사진 표시 |
| 11. 정산 | 관리자 | `/admin/settlements` → `/admin/settlements/:id` | 4절 참고 |

## 4. 정산

정산은 말일이 지난 달만 만들 수 있다. 새로 만든 주문은 구매확정 시각을 기준으로 그 달 정산에 들어가므로, 다음 달 1일이 지나야 그 달 정산을 만들 수 있다. 그래서 시연에서는 관리자 `/admin/settlements`에서 지난달의 PENDING 정산을 열어 "확정" → "지급완료" 순서로 보여 준다. 취소·반품 환불은 구매확정한 품목에서만 차감되므로 이번 시연의 취소·반품은 정산 화면에 나오지 않는다.

## 5. 주의

- 관리자 데모 계정은 실제 최고관리자 권한이다. 셀러 정지, 상품 판매중지, 역할 변경은 시연 데이터를 망가뜨리므로 하지 않는다.
- 공유 데모 계정(구매자 데모 로그인 포함)은 다른 방문자와 데이터가 섞인다.
- 결제 화면에 30분 넘게 머물면 결제가 만료된다.
- 취소는 송장 등록 전 품목만, 반품은 배송완료 후 7일 이내에만 요청할 수 있다. 구매확정한 품목은 취소·반품·교환 모두 안 된다.
