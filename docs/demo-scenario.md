# 시연 시나리오

## 1. 목적

구매자·셀러·관리자 3역할을 오가며 가입부터 정산까지 한 흐름으로 30분 안에 확인하는 시연 순서다. 화면별 세부 조작은 [관련 자료](#6-관련-자료)에 맡기고, 이 문서는 역할을 바꾸는 순서, 품목 준비, 단계마다 확인할 곳만 적는다.

## 2. 준비

**로그인.** 구매자는 `/signup`에서 새로 가입한다. 공유 데모 계정의 주문·클레임과 섞이지 않게 하기 위해서다. 가입하면 바로 로그인된다. 셀러는 `/seller/login`의 "셀러 데모 로그인" 버튼(데모 패션랩)을, 관리자는 `/admin/login`의 "관리자 데모 로그인" 버튼을 쓴다. 역할마다 브라우저 창(또는 시크릿 창)을 따로 두면 전환이 빠르다.

**주문 구성.** 한 주문에 데모 패션랩 상품 2개와 다른 데모 셀러 상품 1개를 담는다. 패션랩 상품 하나는 구매확정용, 다른 하나는 반품용이고, 다른 셀러 상품은 취소용이다. 이 구분은 시스템이 나누는 것이 아니라 시연에서 품목마다 맡기는 역할이다.

## 3. 순서

| 단계 | 역할 | 화면 경로 | 확인 포인트 |
|---|---|---|---|
| 1. 가입 | 구매자 | `/signup` | 가입 직후 로그인 상태 |
| 2. 탐색·장바구니 | 구매자 | `/products` → `/cart` | 장바구니에 셀러 2곳의 상품 3개가 담김 |
| 3. 주문·mock 결제 | 구매자 | `/checkout` → `/payment/mock`에서 SUCCESS | 결제 완료 화면 · 주문 상세에서 품목 3개 결제완료 |
| 4. 셀러별 표시 확인 | 구매자·셀러 | `/orders/:id` · `/seller/orders` | 구매자 주문 상세가 셀러별로 묶여 보임 · 패션랩 셀러 화면에는 자기 품목 2개만 보임 |
| 5. 취소 | 구매자 → 관리자 | `/claims/new` → `/admin/orders/claims` "승인" | 송장 등록 전 품목(취소용)만 취소 가능 · 승인 뒤 환불 완료, 품목 취소 |
| 6. 송장·배송완료 | 셀러 | `/seller/orders`(송장 등록) → `/seller/deliveries`(배송완료) | 패션랩 품목 2개가 배송완료로 바뀜 |
| 7. 구매확정 | 구매자 | `/orders/:id` | 구매확정용 품목만 확정 · 확정 뒤에는 반품·교환 불가 |
| 8. 반품 요청 | 구매자 | `/claims/new` | 반품용 품목 · 사유 "상품 불량" · 사진 첨부 |
| 9. 반품 처리 | 관리자 | `/admin/orders/claims` "승인" → "회수 송장 대행 등록" → "회수 확인" → "검수" | 검수 통과 뒤 자동 환불 |
| 10. 환불 완료 | 구매자·관리자 | `/claims/:id` · `/admin/orders/:id` | 양쪽에서 환불 완료 · 첨부 사진 표시 |
| 11. 정산 | 관리자 | `/admin/settlements` → `/admin/settlements/:id` | 4절 참고 |

### 구매자 데모 계정 — 구매확정·리뷰

`/login`의 "데모 계정으로 둘러보기"(공유 데모 계정)로 들어간다. 이 계정에는 시더 `delivered` 단계가 자동확정 기간(배송완료 후 7일) 안의 배송완료 품목을 채워 둔다([scripts/demo-seed/README.md](../scripts/demo-seed/README.md) 106 데이터 단계). 다른 방문자가 먼저 확정했으면 시더를 다시 실행해 채운다.

| 단계 | 화면 경로 | 조작 | 확인 포인트 |
|---|---|---|---|
| 1. 배송완료 품목 찾기 | `/orders` → `/orders/:id` | 마이페이지 홈의 "확정하러 가기"로도 이동 | 배송완료 품목에 "구매확정" 버튼 · "배송완료 7일 후 자동 구매확정됩니다." |
| 2. 구매확정 | `/orders/:id` | "구매확정" → 확인 창 "구매 확정하기" | 확인 창에 반품·교환 불가 경고 · "구매확정이 완료되었습니다." |
| 3. 리뷰 작성 | `/orders/:id` → `/reviews/new` | "방금 확정한 상품, 어땠나요?"의 별을 눌러 진입 → 별점 · 키워드(선택) · 사진(선택 · 최대 5장) · 리뷰 내용 → "리뷰 등록" | "리뷰가 등록되었습니다." → "상품 페이지에서 보기" · 주문 상세에는 "리뷰 수정" 링크 |

### 구매자 상호작용 (Track 106)

공개 데모 구매자에게는 시더 `inquiries`·`qna` 단계가 답변된·미답변 문의와 질문을 채워 둔다. 셀러 답변은 셀러 데모 로그인, 문의 답변은 관리자 데모 로그인으로 한다.

| 단계 | 역할 | 화면 경로 | 조작 | 확인 포인트 |
|---|---|---|---|---|
| Q&A 즉시 답 | 구매자 | `/products/:id` "이 상품, 물어보세요"(또는 섹션 바 "물어보기") | 궁금한 점 입력(2자 이상) | "이런 답이 있어요" 카드에 기존 Q&A·리뷰·상품 설명에서 찾은 답과 출처 |
| Q&A 질문·셀러 답변 | 구매자 → 셀러 | 같은 곳 → `/seller/products/questions` | "해결되지 않았어요 → 셀러에게 질문 남기기" → 셀러 "답변하기" → "등록" | 질문은 공개 등록 · 구매자 마이페이지 "내 질문"(`/mypage/questions`)에 "셀러 답변" |
| 채팅 도우미(FAQ) | 구매자 | 구매자 화면 오른쪽 아래 도우미 버튼 | 카테고리 칩(주문·결제 · 배송 · 취소·반품·교환 · 회원·계정 · 리뷰·문의)을 고르거나 직접 입력 | 자주 묻는 질문 답변 · "운영자에게 남기기"로 문의 작성 화면 이동 |
| 운영자 문의 | 구매자 → 관리자 | `/mypage/inquiries/new` → `/admin/inquiries` | "운영자에게 문의"에서 문의 종류 · 관련 주문(선택) · 문의 내용 → "문의 남기기" → 관리자 "답변하기" → "등록" | 구매자 "내 문의"(`/mypage/inquiries`)에서 항목을 펼쳐 "운영자 답변" 확인 |
| 리뷰 노출 | 구매자 | `/products/:id` 섹션 바 "리뷰 N" | 필터(사진만 · 키워드) · 정렬(도움순 · 최신순) | 평균 · 별점 분포 · 많이 고른 키워드 · 한 줄 요약 |

## 4. 정산

정산은 말일이 지난 달만 만들 수 있다. 새로 만든 주문은 구매확정 시각을 기준으로 그 달 정산에 들어가므로, 다음 달 1일이 지나야 그 달 정산을 만들 수 있다. 그래서 시연에서는 관리자 `/admin/settlements`에서 지난달의 PENDING 정산을 열어 "확정" → "지급완료" 순서로 보여 준다. 취소·반품 환불은 구매확정한 품목에서만 차감되므로 이번 시연의 취소·반품은 정산 화면에 나오지 않는다.

신규 주문의 정산 편입 실측: 2026-10-01 관리자가 9월 정산을 수동 생성했다. 2026-09-29 신규 가입 구매자의 구매확정 품목이 리빙샵·패션랩 9월 정산에 편입됐다(미편입 CONFIRMED 0건). 두 건을 확정·지급완료했으며, 확정·지급은 관리자 API로 처리했다.

## 5. 주의

- 관리자 데모 로그인은 공개 데모 세션이다. 주문·클레임·정산 같은 업무는 그대로 처리되지만, 계정·권한 변경(임시 비밀번호·탈퇴·역할 회수·구성원 변경 등)과 데모 셀러 정지는 시스템이 403으로 막는다(D-254 · D-255). 상품 판매중지는 막히지 않으므로 시연 데이터를 망가뜨리지 않게 하지 않는다.
- 공유 데모 계정(구매자 데모 로그인 포함)은 다른 방문자와 데이터가 섞인다.
- 결제 화면에 30분 넘게 머물면 결제가 만료된다.
- 취소는 송장 등록 전 품목만, 반품은 배송완료 후 7일 이내에만 요청할 수 있다. 구매확정한 품목은 취소·반품·교환 모두 안 된다.
